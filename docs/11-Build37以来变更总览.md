## 本轮结果与接续

- 用户要求：查明选卡快捷键覆盖血量显示的问题，修复后梳理大约Build37以后的全部改动；追加要求是血量必须用常用键，不能用Fn键。
- 已查明：Win32与SDL都输出VK兼容键码，字母键为大写；小写`t`的数值等于F5，小写`v`等于F7，小写`b`等于小键盘2。旧协作KeyDown误把键码当大小写字符，提前吃掉功能键/数字键。不是只把1/2改名就能修好。
- 当前代码：双端H=僵尸、J=植物；移除协作KeyDown的小写别名，保留KeyChar文本大小写；H/J长按不反复切换，不再触发调试刷怪。Android补己方血量数字绘制，未加触屏设置开关。
- PC Release和Android Native编译通过。真实WidgetManager→Board→协作处理器、双原生会话与800×600离屏渲染9项检查通过；证据在仓库外`android-artifacts/keyboard-health/`，源码`tools/keyboard_health_probe.cpp`。僵尸标签亮字像素0→86，植物0→50，长按保持，关闭后均回0。不是硬件按键或移动运行全链验收，也没有重跑全buff。
- 已整理Build37–53的完整主线、被替代规则及161笔PC/31笔Android基线历史索引，并另列本轮收口提交；其他agent的Android功能审计是`ed8fb76`，保留其退出、存档、触摸等缺口。收口时另一agent已提交植物候选跨屏冷却`2eb8646`，见下方追加，不是本轮代提交。PC的`tools/symbols/`与本轮无关。
- 后续从Android `docs/KEYBOARD-HEALTH-FIX-STATUS.md`看来源/产物。先完成触摸血量设置及功能审计的退出/保存闭环，再做必要设备定点；保护当前运行中的玩家对局，不自动覆盖旧进程。

## 当前玩家快捷键

| 按键 | 功能 | 场景/优先级 |
|---|---|---|
| 键盘上排1–9、0 | 种子栏第1–10格 | 普通战斗；消息、表情、送阳光与观战选人优先消费数字 |
| Q | 拿铲子 | 仍需点击草坪铲除；特殊工具/传送带沿原行为 |
| H / J | 僵尸 / 植物血量数字开关 | 常用字母键，不依赖Fn；H同时显示本体、帽子、盾牌、气球血量；本机显示，不改数值 |
| T / E | 快捷消息 / 植物表情 | 面板中1–9发短语、1–8发表情，Esc关闭 |
| G、1–6 | 送阳光并选队友 | 扣100到账90；G/Esc取消，选择态数字不同时选卡 |
| B | 协作：借用/求援 | 借用在准备阶段，阳光求援在战斗；大厅换位从席位UI发起 |
| V | 观战 | PC按住，1–6选队友、松手返回；Android按一下进入/退出、右方向键换人 |
| Space / Esc | 暂停；取消选择或打开菜单 | 模态框/观战/协作选择态先处理；不是全局穿透键 |
| Alt+Enter | PC窗口/无边框全屏切换 | 本地窗口行为 |

小键盘需NumLock开启；CapsLock/Shift不影响这些物理字母键。输入框和模态对话框有自己的焦点；不能承诺在聊天/观战面板内H/J穿透切换草坪显示。游戏调试键（如`-tod`下M加币/强制投票）不列作普通玩家功能。
