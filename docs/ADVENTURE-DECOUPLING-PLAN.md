# 双端冒险流程依赖排查与修复计划

2026-10-15。用户明确：不会游玩完整原版冒险流程；先对齐 PC/Android 的共同功能，Android 多出的小游戏、解谜和商店页保留，不做功能删减。本轮只排查与计划，不修改游戏代码、存档或安装包。

排查基线：Android `49b683a`，PC `946f690`。PC已有仓库外工具的未跟踪改动，本轮未触碰。

收尾发现Android的 `src/Lawn/Run/RunBuffs.cpp/.h` 出现外部未提交改动，本轮没有编辑或暂存它们；后续实施保留其内容，目录及候选表以实施前实际状态复核。

## 结论与边界

共同功能必须在新档案、未通关冒险时就能使用；闯关卡池、难度与联机行为不受本机冒险进度/购买记录影响。保留金币、花园植物、工具购买、库存、养护和出售的正常成长。不得通过修改 `mFinishedAdventure`、把 `HasFinishedAdventure()` 全局改成 true 或灌入通关档来实现开放，这会引入二周目、选卡、奖励、雪人准入等副作用。

额外原版内容不等于共同功能差异：不把 Android 四页商店删成 PC 两页，不移除小游戏/解谜/原版生存，也不在本批强行给 PC 恢复所有旧入口。额外内容的冒险门槛单列排查，先保证它们不会卡住共同功能。

## 植物掉落的完整链路

`Zombie::DropLoot` → `Board::DropLootPiece` → 掉落资格/花园容量 → 原概率抽样 → `COIN_PRESENT_PLANT` → 按关卡场景选植物 → `Coin::Collect` → 花园容量复查 → `ZenGarden::AddPottedPlant` → 档案保存。

- 普通礼盒来自击杀抽样；不是击杀某植物僵尸就掉对应盆栽，也不是闯关三选一的植物直接进入花园。
- 植物礼盒按白天/夜晚/泳池/雾/屋顶的植物表抽取；原版无尽生存等走随机普通植物表，不包括升级植物、模仿者等全部战斗卡。保持PC现行候选表，不擅自扩池。
- 主花园32格。地上未领取的植物礼盒计入掉落容量；领取时复查实际已入园数量。正常满园不再掉，不能当成随机故障。
- PC现行阈值算法基于 `Rand(30000)`，冒险复玩分支24、其它模式12、原版无尽生存3，再乘僵尸掉落因子。自定义闯关使用冒险引擎，不能简单宣传为统一固定百分比。此次保留阈值、价格、币值和候选表，只移除不应存在的冒险门槛及Android替换。
- 两端保留 `mTotalSpawnedWaves > 70` 的旧掉落停止条件；自定义无尽会保留草坪、该计数未在续关重新赋零。这是独立的长局掉落策略，记录为待评估，不在“冒险解锁”名义下静默取消。
- 原版特殊挑战也可能通过 `COIN_AWARD_PRESENT` 发奖；应与普通击杀掉落一起核对，避免只修普通礼盒漏掉奖励入口。

## 实施顺序

1. **共同功能开放（P0）**：先明确“可访问图鉴/商店/花园”“可获得/购买/出售花园植物”的独立条件。PC修复共同隐藏门槛；Android同批对齐入口与图鉴内部，保留额外商店页。显示范围、点击范围和资源预加载一并核对，防止页面开放了但未解锁资源尚未加载。功能开放不改冒险通关记录，不附赠已购买工具或刷入植物。
2. **花园经济闭环（P0）**：两端开放植物掉落、盆栽购买、出售；Android移除吞礼盒分支。核对领取/购买/出售后的保存、满园和库存上限。商店内原有工具依赖、每日限购、冷却和养护流程保持。
3. **闯关隔离补齐（P1）**：移植PC缺失守卫，包括选卡行数、钻石升档、非闯关联机急救、配乐和潜在戴夫问候；确认新档/老通关档/买满商店档在同一闯关规则下一致。已有强制选卡保护保留。
4. **流程与图鉴收尾（P1）**：图鉴费用/冷却与词条按钮分离，补稀有度；检查空花园首次进入不会等待第45关教程才可操作，已有教程不会重复赠送植物。保留联机房间时出入本地花园/智慧树不会触发队伍开局/结算。
5. **额外内容后续清单（P2）**：Android小游戏/解谜/原版生存入口及挑战列表仍有冒险/奖杯门槛，额外升级商品也依赖冒险进度。保留这些功能，逐项区分“冒险硬门槛”和“本玩法内解锁”；不扩大本批为恢复PC全部原版模式，也不免费解锁购买效果或抹掉本玩法的成绩。
