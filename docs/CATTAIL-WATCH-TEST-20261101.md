# 三株猫尾草观战实测

使用已交付的 MOD104-RoomP2P-Test 原二进制；没有修改游戏逻辑或重新打包。本次只新增后台测试脚本和证据。

## 场景

隔离实例 CattailA / CattailB，从此前隔离测试档复制已有猫尾草卡组，继续普通模式、标准 ×1。双方显式带 `-bench-edge-kill=1`，僵尸到底线死亡。通过后台接口实际拾取阳光、点击卡槽种植；没有直接写阳光、冷却、植物或僵尸内存。三株猫尾草放在中间三行，五株向日葵供给阳光。音乐关闭，未发送系统鼠标输入。

最初未开底线死亡的尝试因漏怪失败，不计为通过；之后按用户指示开启。底线死亡不保护植物，后半程猫尾草仍会被僵尸吃掉，不能把后半程全部计为三株同时攻击。

## 结果

- 三株在场期间已记录真实跨行追踪针、命中和目标死亡；对照图中的主要追踪弹和既有僵尸位置接近，没有发现追踪针不飞、无法命中或恢复崩溃。
- 当前订阅实际接收 57 份有效 P2P 帧；观战子进程共成功恢复 58 次，失败 0 次（包含首包服务器传输）。
- 来源战场最高 28 只僵尸；三株在场采样中最高同时 15 枚子弹。
- 来源采集加压缩/排队平均约 1.539 ms，最高 4.513 ms。这不是渲染帧耗时，也不能据此声称绝无卡顿。
- **发现预测偏差：部分新一波僵尸的出生行不同。** 166.189 秒对照图中，右侧新出现的僵尸分布不同，已在场的僵尸及追踪针则较接近。后续快照能重新对齐，但纠正可能表现为跳动。因此不能把本次测试描述为观战完全一致。

代码检查发现两个相关风险：PWV2 尚未传输 `mRowPickingArray`（出怪选行的平滑历史状态）；观战端直接跳过天空阳光生成，与来源端消耗随机数的路径不同。虽然包里携带全局随机数状态，两个快照之间仍可能分叉。这些是已确认的实现差异；本次没有通过修复前后 A/B 实验证明各自贡献，暂不将任意一项单独认定为全部根因。
