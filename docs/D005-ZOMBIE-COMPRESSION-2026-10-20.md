# D005 高密度波次减量：规则定案与首批范围

日期：2026-10-20。状态：用户规则已确认；等待集中调度协调共享文件写入。尚未修改玩法源码、正式版本号、构建目录、安装包或 runtime。

## 用户最终定案

1. 仅新开的闯关与无尽使用新规则，PC / Android 一致。已有存档沿用原规则。
2. 原波实际自然出怪条目数 N 不超过 80 时不变；超过 80 时保留 `80 + floor((N - 80) / 2)` 个条目。这里的 N 是原规则实际生成的波表长度，不是该波理论上限或当前场上僵尸总数。
3. 原僵尸点数预算、随机选怪逻辑、兵种解锁和现有特殊怪限制不变。用户最终选择“只减少名额，完全保留现有随机选怪逻辑；接受强度可能下降”。此前讨论的装甲配比、替换名额、额外耐久/啃咬补偿均被此选择取代，不实现。
4. 保留 Boss 和旗手；其他自然出怪可参与减量。伴舞、小鬼等召唤机制及数量首批保持。接力怪不再次压缩、不重复强化，保留上游实际剩余血量。
5. 保持现有逐只掉落，接受怪少后收益减少；吸金磁仍按实际吸收的币结算，不额外补偿。
6. 首批不含用于控制场上峰值的完整等待入场队列。稳定性任务对满池、接力失败、溢出的处理独立，由调度分配，本任务不占其实现职责。

整数边界示例：80→80，81→80，100→90，200→140，640→360，1280→680。Boss 在波表之外生成，不计入 N；旗手计入原波长度、保留其条目，占最终名额。召唤出来的额外实体不计入 N，所以最终实际生成实体数或同时在场数量不等于这里的条目数。

## 最小首批实现路径（拟案，待调度确认文件归属）

保持原波表生成与随机数调用顺序，全部原波表构建完成后，使用独立、可复现的压缩过程处理超 80 条目的波表。保留条目来自原波表，不重抽、不换类型、不增权、不调整预算。这样无需将“原波实际条目数”误写成“理论上限”，也避免重建前一波改变后面波次的随机抽取。

## 首批验收矩阵

1. 数量公式：0、1、79、80、81、82、99、100、200、640、1280、1599；终止符、数组边界、保留条目数一致。
2. 差分：旧规则波表逐项及共享 RNG 后续结果与基线相同；新规则 N≤80 时逐项相同；N>80 仅移除条目，无新类型或额外数值改动。
3. 构成约束：旗手/必要条目保持；Boss 单独生成流程不变；巨人和舞王不超过原上限；场景、水路、屋顶、新无尽主题仍使用原合法波表。
4. 持久化：旧闯关、旧无尽、新规则闯关、新规则无尽分别覆盖新开、关间续局、完整棋盘保存恢复、失败重试；恢复不能二次压缩。
5. 联机规则：双端收到相同新旧局标记，主机新开/旧档续局、重试、晚到/重连场景不自行切换规则。接力单位属性与原接力语义一致。
6. 行为：自动波次和手动下一波规则保持；不增加等待入场队列；召唤数量保持；掉落与吸金磁仍按实际击杀/吸币，不引入补偿。
7. 性能：同关、同种子和相同阵容对比波表数量、实体峰值、逻辑更新耗时，分别记录 PC 与 Android 可取得的证据。不把 PC 探针结果当安卓真机结论，不声称保证不闪退或难度等价。
