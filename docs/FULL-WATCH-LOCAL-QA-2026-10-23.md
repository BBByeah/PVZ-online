## 实测

- 完整 Release 游戏成功编译、链接。`build-rel-x86/SexyAppFramework.exe`。
- `tools/full_watch_live_probe.cpp` 只替换测试程序入口，链接同一批游戏对象文件；启动两个独立游戏进程，通过 `127.0.0.1:28463` 真实 TCP 直连。使用独立的 QA-A、QA-B 存档，没有加载或覆盖玩家存档。
- 测试入口自动准备不同草坪与肉鸽状态，通过现有游戏内观战动作进入；实际观战恢复由普通 LawnApp 辅助进程执行。
- A 阳光 1111，B 阳光 2222，双方 8 个卡槽。B 观战显示 A 的 1111 和 8 个卡槽，返回后 B 仍为 2222、8 个卡槽，自家模拟持续推进。
- F10 再次进入成功；向实际观战窗口发送 Esc 后订阅退出、辅助进程结束。
- 800×600 原生观战画面中草坪和植物、僵尸正常；阳光数值保留，场上阳光隐藏。截图草坪采样区黄色像素：主场 3074，观战 0。
- 实际完整快照约 668–677 KB，压缩后约 4.7–5.8 KB。恢复日志同时记录原生 Board、RUN1、卡槽和阳光信息。
- 测试进程均已结束，没有留下后台测试游戏。测试证据位于 `build-rel-x86/live-test/`（不入 Git）。

## 实测修复

最初恢复直接调用 `LawnLoadGame`，只还原对象数据，未完成背景资源和绘制层更新，导致加载画面残留。改为调用 `Board::LoadGame`，复测确认草坪恢复正常。

本地构建还修正了图像依赖的 Release 库名、构建类型传递和 libpng 的 ZLIB 查找参数。SDK 采用项目旁的本地文件，不修改系统 SDK 安装。

## 边界

本次验证为短时、本机双端直连与原生渲染，不涵盖公网中继、六人压力、全部地图或长时间稳定性。程序化测试入口没有逐步点击建房和选卡菜单。测试程序不作为玩家发布版。
