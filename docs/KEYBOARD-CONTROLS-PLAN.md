# 种子栏与铲子快捷键计划

2026-10-14 制定方案；2026-10-15 Android 已实施，结果与未验边界见 [执行记录](KEYBOARD-CONTROLS-STATUS.md)。PC 同步仍待独立批次完成，下文保留实施方案。

用户确认：**1–9 选前九张植物卡，0 选第十张，Q 拿铲子**。PC 与 Android 外接键盘/MuMu 使用同一套默认方案；手机触屏继续使用种子卡、铲子和已有拖动流程。

## 默认键位与优先级

| 场景 | 按键 | 行为 |
|---|---|---|
| 普通战斗 | 1–9、0 | 按种子栏从左到右选择第 1–10 个槽位，不按植物 ID 绑定 |
| 普通战斗 | Q | 拿起铲子，随后点击草坪铲除；铲子未开放时不生效 |
| 持卡或持铲 | ESC | 取消当前选择，沿现有取消流程 |
| 无选择 | ESC / Space | 沿现有菜单/暂停行为 |
| 消息、表情页已打开 | 1–8 | 发送面板对应项目，数字键不同时选植物 |
| 送阳光选择态 | 1–6 | 选择对应队友席位，沿 PC 资格、金额与冷却 |
| PC 观战中 | 1–6 | 切换观看席位，不选本地植物 |
| PC 血量显示 | F5 / F6 | 分别切换僵尸/植物血量数字，替代原 1/2 |

T/E/G 保留消息、表情、送阳光入口；PC 按住 V 观战保持现状。协作面板已有的关闭、切页和超时语义继续沿用；面板打开时 Q 也不穿透拿铲子。Android 观战尚待迁入，提前保留这一层输入优先级。

输入顺序为：编辑框与模态界面的焦点路由 → 已打开的协作/观战选择态 → 可用的战斗快捷键 → 原有其它键。选卡、奖励、投票、菜单、房间地址/房间码编辑时不通过数字键拿植物。Ctrl/Alt 等组合键不当作普通选卡键；Q 按物理键处理，不要求输入小写字符。

## 源码核对与冲突

- Android 起点 `ad7a541`，固定玩法来源仍为 PC Build 46 / `8bfc67ea9c85be37cac0a182c3416f3add2c1640`。Android `Board::KeyDown` 已接 T/E/G，尚无数字选卡和键盘铲子，也未迁入 PC 的血量数字开关。
- 只读核对 PC 固定来源及当前已提交 `c5ccdbe27dc824c8613d461cbf5bc06b6f259750`：局内数字 1/2 切换血量显示，协作与观战选择态先处理数字键。更新快捷键需要明确替换 1/2，不能保留两套同时触发。
- PC 全局调试入口已经使用 F2（性能）和 F3（帧率），因此不采用 F1/F2 配对。已提交源码中 F5/F6 仅有键码定义/名称，计划用作血量显示；实施前若 PC 已更新，再核对新增绑定。
- PC `Board::KeyChar` 的调试路径存在 6/7/8（速度/易种植）以及 q（无尽调试）等占用。新的战斗按键在 KeyDown 消费后，还须防止同一次输入继续在 KeyChar 执行作弊。只调整战斗已接管按键的字符路由，不直接删除树苗等其它场景的调试功能。
- PC 工作目录由其它工作使用；本轮及 Android 实施不修改该目录。PC 改动单列为同步任务，在独立分支或已授权的同步批次落地；Android 提交不表示 PC 已更新。键位属于本地输入，不要求修改联机协议、植物数值或存档格式。

## 选择行为

1. 按键只拿起植物或铲子，不直接种植、铲除、花阳光或跳过冷却。不存在的槽位忽略；不足阳光、冷却中及升级前置条件不满足，沿原种子卡的拒绝提示与规则。
2. 已持有同一张卡，再按对应键保持选择；已拿铲子，再按 Q 保持铲子。切到另一张可用卡或铲子，先按现有归还路径处理旧选择，再拿新对象。切到不可用卡时保留旧选择，不通过归还旧卡来刷新目标冷却。
3. 复用 `SeedPacket::CanPickUp` / `SeedPacket::MouseDown` 与 `Board::RefreshSeedPacketFromCursor` / `PickUpTool` / `UpdateCursor`。必要时提取很小的共用选择入口以复用拒绝提示；不手写一套种植资格、不模拟屏幕坐标点击、不直接改卡片激活状态绕过规则。
4. 持卡时 `CanInteractWithBoardButtons()` 本身会返回 false，不能直接拿它作为全部快捷键的开关。入口需单独核对战斗场景、暂停、模态框、失焦、退关、对白/教程、铲子可见性以及鼠标点击原有条件；允许普通种子卡与铲子之间切换，特殊光标（掉落卡、玉米炮瞄准等）不强行替换。
5. 正在触屏拖动或其它鼠标手势时，不响应新选卡/拿铲按键，避免抬手误种或误铲。键盘拿卡不设置 Android 的 `mTouchSeedDrag`，也不改变已有拖动取消/松手种植规则。
6. 每次按下只处理一次；长按不连续拿卡、播放音效或铲除。按键释放、失焦、退出战斗时清理按住状态。模态面板关闭后仍按住的数字键须先释放，不能把同一次长按转成选植物。
7. 支持主键盘数字和 NumLock 下的小键盘数字。先核对 Windows/SDL 的实际键码转换，再统一映射；NumLock 关闭时导航键仍作导航键。种子槽位按当时顺序取卡，不缓存跨关指针。

首批覆盖普通种子栏的冒险、闯关与生存战斗。传送带可按当前可见槽位选择，但需核对其点击/移除语义后再开放；老虎机、宝石迷阵、僵尸水族馆、花园、智慧树及特殊工具玩法不借用普通选卡入口。教程只在正常点击已允许的阶段接入，不能越过原有门槛。

## UI 与实施拆分

1. **输入与动作**：在 Android Board 接入数字/Q、场景和手势检查、选择切换及按键释放；核对 SDL 键码与字符事件。先完成正确操作，再做提示。
2. **显示提示**：PC 种子卡角落标 1–9/0，铲子旁标 Q；Android 在检测到键盘输入后显示提示，触屏用户不弹软键盘。沿用游戏字体与卡片/工具布局，不覆盖植物图、阳光费用或冷却遮罩；键位帮助同时有中英文。该项加入原版风格 UI 盘点。
3. **PC 同步**：在独立同步工作中采用相同动作入口与默认键位，将血量 1/2 移到 F5/F6，解决 KeyChar 的调试冲突，并更新 PC 操作说明。PC 尚未同步时如实记录差异；这一批不自动提高 Android 固定玩法来源版本。

暂不建设完整可配置键位系统；默认表集中定义，便于以后加设置页。MuMu 需要把按键传给应用，模拟器自身按键映射若拦截同一个键则应解除冲突，不默认依靠十组屏幕点击映射实现功能。

## 有限验收

实现后进行一次增量原生与 APK 构建；在 MuMu 的十卡局检查 1、9、0 和 Q，代表性完成一次键盘选卡后种植、一次铲除。补一次持卡切换/不可用卡拒绝，以及长按/失焦后的状态检查。

在同一路径开消息页按 1，确认只发消息、不拿植物；送阳光选择态确认数字只选择席位。暂停或编辑房间码时数字不影响草坪。主键盘与小键盘各做代表检查，触屏拖动只复查一例混合输入。

PC 落地后定点确认 F5/F6 仅切换显示、1/2 仅选卡，调试打开时 6/7/8/Q 不再双触发；观战中数字仅切观看席位。不开全量 buff 回归，不重复测试十种植物同一入口，不建立大规模键盘测试框架。记录实际验证的平台与未验边界。
