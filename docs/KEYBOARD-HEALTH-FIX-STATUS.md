# H/J血量键与Build37以后变更梳理交接

2026-10-16。本轮已修双端键路由与PC定点，不要求玩家使用Fn键。独立的全功能审计F01/F02/F03等问题仍按原计划处理，不能把本轮当成全功能对齐。

## 最终行为

- 键盘上排1–9/0种子栏、Q铲子；**H僵尸血量，J植物血量**，本机显示，不改实体数值；消息/表情/赠送/观战面板的数字优先。
- 字母VK统一大写：去掉KeyDown/KeyUp的小写字母别名，修NumPad2误触B、F5误触T、F7误触V。Win32及SDL本来都把物理字母映射为大写VK，CapsLock/Shift照常。
- H/J自动重复不切换；KeyChar不再同时刷调试僵尸。正常文本字符处理不做全局大小写强改。
- Android补己方植物/僵尸精确血量数字（含防具），复用PC白字黑边与本机偏好语义，不加Board字段或改保存布局；选项键位提示包含H/J。**尚未补普通手机触摸开关**，不能把F06触摸入口一起标完。
- B/T/E/G/V入口本身保留；PC按住V，Android按一下V进入/退出、右键换人。准备阶段B借用与战斗B求援沿原阶段门。

## 原因与证据

F5=0x74=ASCII小写t，F7=0x76=v，NumPad2=0x62=b。旧处理器接受小写字符，从而把键码误认成字母。旧Build49抽函数测试使用mock协作入口，未覆盖此问题；本轮改用真实处理器。

- PC Release / Android Native通过，日志在仓库外`android-artifacts/keyboard-health/`。
- `tools/keyboard_health_probe.cpp`在独立产品PvZKeyboardHealthProbe中运行，用真实WidgetManager→Board和双原生NetSession；9项检查：连接、H不误开聊天、数字血量真实绘制、功能键不冒充T/V、上排1/2/0选择第1/2/10槽、可选小键盘兼容选槽2、T开消息、面板内小键盘2选消息、H/J不额外刷怪，全部1。
- 800×600游戏离屏绘制：`health-off.bmp`、`zombie-health.bmp`、`both-health.bmp`、`held-h.bmp`、`plant-health.bmp`、`health-restored.bmp`。H后僵尸270本体/370路锥可见，J后向日葵300可见。
- 标签区域亮字像素：僵尸0→86、植物0→50；长按不变、关闭后回0。字体白色经过纹理/混合为254附近，按各通道≥250计数，未假设每个亮字点都是255纯白。
- 无硬件键盘/Win32消息完整链或Android设备运行验收；没有重跑整关/buff。没有关闭或替换用户当前PC进程，没有操作原玩家存档。
