## 已实现

- 战斗左侧三个常驻石材按钮：消息、表情、阳光。短语八项、表情 2×4 使用 PC 编号/文案/植物图；本机语言决定显示，不改线上编号。
- 消息成功发送后回显，接收显示名字与席位，最多三条横幅。打开面板时只显示最近一条，避免遮挡选项；队列与计时保留 PC 常量。
- 阳光选择队友，扣 100、到账 90；自己/空席位不可送，冷却 300 逻辑帧，失败退回并清冷却。收方上限 9990、显示发送者，三枚展示阳光不二次入账，也不计入在途种植预算。
- 非模态触屏面板，抬手选项才发，拖过不同格子不连发；关闭点击由协作层消费，持卡不主动清掉。暂停、掉线/退出和失去焦点时收起输入状态；键盘 T/E/G 与 1–8/1–6 仍可使用。
- UI 使用现有石材按钮和对话框素材、中英文 UTF-8 字体；整体原版风格替换尚未执行。

## 有限验证与边界

真实 MuMu Android 15 与从固定提交导出的 Windows NetSession/Win32 NetLink 原生验证端连接，双方握手显示 Build 46。验证端不是完整 PC 游戏，没有模拟 PC 战斗或钱包。

- 双向短语与植物表情发送/接收通过，验证端收到 Android 的 ID 1 和 11。实际收到 90 后，Android 阳光 50→140；发送一次后 140→40，验证端收到 90。冷却与余额不足提示通过，未出现额外阳光入账。
- 受控 OPEN 消息使 Android 显示投票面板；实际点选后验证端收到 `level=5, choice=0`，结果消息关闭面板。早期检查另观察到客户端双倍超时自动关闭。此项不替代正常跨场景开票或多人退房计票实战。
- 38 字节血量/首领编码、旧 22 字节拒绝、场景号 500 的投票编码、重复候选拒绝及饱和计算代表检查通过。
- 增量 Native/Gradle、固定来源检查通过。未重跑所有 buff、短语/表情或完整关卡。

完整 PC 游戏、中继下协作、正常整队跨关/重试、三人以上投票、真机与前后台断线恢复仍待代表验收。`onlineGameReady=false` 保留。PC 实际运行包需更新至相同 Build 46；旧 Build 45 即使能入房，也不保证漏怪/投票兼容。
