# 当前玩家快捷键

2026-10-16，Build53本地输入修复。**血量改用H/J常用字母键，不需要Fn。** 旧文档的1/2和F5/F6血量绑定已失效。完整版本梳理见[Build37以来总览](11-Build37以来变更总览.md)。

| 键 | 功能 |
|---|---|
| 键盘上排1–9 / 0 | 种子栏第1–9格 / 第10格 |
| Q | 拿铲子，之后点击草坪铲除 |
| H | 僵尸血量数字开关，含本体/帽子/盾牌/气球各自当前生命 |
| J | 植物当前血量数字开关 |
| T / E | 快捷短语 / 植物表情，面板内数字选择 |
| G、1–6 | 送阳光并指定队友：扣100到账90，G/Esc取消 |
| B | 协作页：准备阶段借用，战斗中求援 |
| 按住V、1–6 | PC观战并选队友，松开V返回；Android改按一下进入/退出，右方向键换人 |
| Space | 战斗暂停，受当前模态/选择态限制 |
| Esc | 关闭当前选择态、取消持卡/工具；无选择时按原流程打开菜单 |
| Alt+Enter | PC窗口/无边框全屏切换 |

默认主操作使用键盘上排数字，不需要小键盘。可选兼容NumLock开启的小键盘；只拿起卡片，之后点击草坪种植。不可用目标沿原规则提示并保留当前持卡，阳光/冷却/解锁不变。CapsLock与Shift不影响物理字母绑定。传送带、特殊小游戏和花园工具保留原操作。

优先级：当前模态焦点 → 协作页/消息/表情/送阳光/观战的专属输入 → 普通战斗选卡与H/J。选择面板会吞自己的输入，H/J不是绕过模态框的全局键。长按数字/Q/H/J只处理首次，不连续选卡或反复切换；暂停、对白、过场、拖动或修饰键门禁继续用于拿卡。血量偏好仅本机、进程内保存，不改实体数值或联机消息。

## 本次根因和修复

Board::KeyDown收到的是VK兼容枚举，不是ASCII文本：F5=0x74恰好是小写`t`，F7=0x76是小写`v`，小键盘2=0x62是小写`b`。旧协作处理器同时比较大小写字符，导致F5被当T开消息、F7被当V观战、小键盘2先开B协作页。字母VK在Win32与SDL中本来统一为大写，因此KeyDown/KeyUp只保留大写比较；真正文本KeyChar仍按字符处理。

按用户要求，血量用H/J取代F5/F6；同时保留数字面板优先。H/J在KeyChar中隔离旧调试刷怪路径，避免`-tod`下一个按键同时切显示和刷怪。选卡页/奖励页的B同样去掉小写别名，避免小键盘2误开协作。Android补了己方草坪血量绘制与相同键路由；普通手机的触摸设置入口仍待后续。

## 验证与交付边界

本轮证据在仓库外`android-artifacts/keyboard-health/`，探针源码为`tools/keyboard_health_probe.cpp`。使用真实引擎WidgetManager→Board→协作处理器及两个原生NetSession，不用mock聊天/观战处理器；真实800×600离屏绘制核对数字开关。它不是硬件键盘/Win32消息全链或完整手机实战的替代品。

旧Build49记录中“F5/F6输入检查通过”来自mock协作处理器，漏了键码碰撞；本文件纠正该结论。历史`a25fcdc`保留，不将其当作本次已修复证据。当前用户运行的旧程序不会因源码提交自动更新，保留玩家对局后再正常替换运行产物。
