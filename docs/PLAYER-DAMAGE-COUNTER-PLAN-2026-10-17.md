## 一、已确认选择与界面建议

- **范围默认“本关”**，进入新关重置本关数值；高级选项提供“本关 / 本轮累计”。本轮累计作为可选范围，闯关从开局累计到胜负，无尽跨波和场景累计，开始新一轮清零。
- **BOSS统计与总统计独立展示、各有开关**，不做强制并排的两列总表。首版两个独立详情面板分别展示，默认两种摘要均显示，可各自关闭；此默认值是实现选择，并非额外玩家定案。
- 高级选项切换范围只改变查看范围，不清空后台已经记录的数据；建议作为本机显示偏好，不替队友改设置，也不改变出怪或伤害规则。已保存的范围选择下次沿用，无配置时默认本关。
- 战斗常驻采用可隐藏的紧凑入口/摘要；点击展开所选类型的全队统计，最多六人，不常驻大表格遮住战场。无BOSS的本关显示0或“本关无BOSS”，不残留上一关的BOSS数字。
- 总统计页与BOSS页各按原席位顺序展示玩家，不默认做输赢排名。各席位怪量不同，伤害高低不等同于贡献高低。
- **已确认计数关系：总统计包含BOSS伤害，BOSS统计是其中的子集，两项不能相加。** 展示/开关分开，不意味着伤害互斥；关闭BOSS显示不从总统计中扣除BOSS伤害，也不停止后台记账。
- 过关/胜负时保存一份可查看的统计摘要，不插入强制弹窗。首版不加入每秒伤害、逐株排行、历史排行榜或浮动伤害数字。
- PC可点击或使用不冲突的快捷键；手机只有触控入口、不显示键盘字母。具体位置须结合现有聊天、阳光、协作、进度和BOSS血条排布，不能先硬塞一行。
- 沿用原石材和已有艺术字，数字完整值在展开页查看，常驻可用万/亿等缩写。新增固定标签先核对原字库，缺字改措辞，不替换或重制资源。

## 二、建议统一的计数规则

| 情况 | 建议规则 |
|---|---|
| 普通伤害 | 记录增伤、护心封顶、护甲分配后，实际造成的生命/有效装备耐久损失，而不是攻击面板或传入参数 |
| 过量伤害 | 目标剩100血，命中1000只计100；免疫、无效命中和已死亡目标计0 |
| 本体、头盔、盾牌、飞行耐久 | 各实际受损部分分别结算再累加；同次攻击确实同时打到盾和本体时两者均计，不把一次伤害重复汇总 |
| 治疗、再生 | 不倒扣已经造成的伤害；回复后再次受到的有效伤害正常新增，所以整轮累计可高于初始总血量 |
| 爆炸、穿透、溅射、反伤、词条持续伤害 | 按每个真实受伤目标/每次生效计入，避免弹体、范围函数和扣血入口重复记账 |
| 吞噬、缠绕、灰烬等玩家秒杀 | 建议折算为被实际消灭的目标剩余本体及有效装备耐久；不能按99999之类固定值，也不能因绕过普通扣血而漏记 |
| 磁力摘装备、三叶草吹走、换道、减速等 | 单纯控制/移除装备不折算伤害；磁力抛掷等真正扣血部分正常计入 |
| 小车、清场脚本、传送删除、尸体自然掉血 | 不记入个人伤害；如以后需要，可单列环境项，不伪装成玩家输出 |
| 魅惑 | 魅惑后的友方僵尸打敌人建议算操作者输出；敌方对友方的扣血不算玩家输出 |
| 借用植物 | 算当前使用者，不回记给出借人；借用和归还不搬动已产生的统计 |
| 接力僵尸 | 各人只记在自己草坪实际造成的新增伤害，移出/接收不计；不能在接收时再用最大血减当前血重复记上家输出 |

需要特别区分“伤害导致扣血”和“生命字段变化”：脱盔、落地、进入死亡状态、初始化、读档、再生、接力覆写都有可能改字段，不能每帧做一次全体血量差就全部算输出。

### BOSS范围

- 使用现有明确BOSS标记识别闯关红眼、橄榄球和冰车，包含接力BOSS和多只并存，不按体型或普通怪种判定。
- 在有效伤害发生前锁定BOSS分类，避免最后一击清状态后漏掉。
- 普通红眼/橄榄球/冰车不因类型相同就计入BOSS；召唤的小怪不进BOSS统计，归普通目标伤害。
- 若后续覆盖原版冒险，原僵王另列明确识别；首版建议先覆盖单机/联机闯关与无尽。

## 三、已核查的现有基础与风险

1. 各玩家有独立棋盘，漏怪通过接力消息传当前/最大血量。首版可把本机有效输出归本机玩家，无需先给所有植物、子弹加所有者字段；跨棋盘直接攻击若后续加入，再单独扩展归属。
2. 两端均有Zombie::TakeDamage，内部处理全局增伤、护心上限，再分发TakeFlyingDamage、TakeShieldDamage、TakeHelmDamage、TakeBodyDamage。记录传入theDamage会把过量与减伤前数值算错。
3. 植物部分吞噬直接调用DieWithLoot；ApplyBurn既可能走TakeDamage，也可能直接进入死亡流程。只钩TakeDamage必然漏计；直接给所有DieWithLoot加剩余血又会把接力、环境和重复死亡算错。
4. 焦土在僵尸更新里调用TakeDamage，地刺反击和魅惑攻击也可能由僵尸侧发起。不能简单地“Projectile才算玩家、Zombie函数都是环境”，也不能把每次TakeDamage无条件算输出。
5. Board::IsRunBossZombie已识别红眼、橄榄球、冰车及接力标记，不应只用mRunBossZombieID；普通同类型僵尸不能混入BOSS列。
6. PC和Android现有保存路径均含Board及池化实体的原始字节同步。不能直接给Board/Zombie/Plant/Projectile追加统计成员或容器，否则旧存档存在布局兼容风险。
7. 现有协作层有会话身份mCoopToken及身份到席位的映射。统计不能只按席位存，否则换位后会把旧人的伤害算给新席位玩家；身份跨进程恢复能力仍需另行设计，不能把会话令牌当永久账号。

这些是静态源码事实，不代表已覆盖所有伤害调用，也不代表功能验证通过。

## 四、实现路线

### 1. 先做可靠的本机计量

- 新增独立统计模块，使用64位累计值；由应用/对局状态持有，不改变现有原始保存对象布局。
- 明确有效伤害事件：对局/关卡/尝试标识、玩家身份、来源分类、目标身份、是否BOSS、有效数值。事件仅本机结算，不逐次发网络包。
- 在实际分层扣血处取得扣除前有效耐久与实际消耗，统一交给单一计量出口；聚合层不再重复计同一笔。
- 为爆炸、吞噬、缠绕、反伤、持续伤害、魅惑等补足来源上下文。环境和无来源事件默认不冒认个人输出；覆盖矩阵必须明确排查遗漏。
- 秒杀专用记账仅在确认玩家造成、目标仍可受击、实际转为死亡时提交；与普通扣血互斥，死亡动画、DropLoot和清理不得再次计数。
- 统计只读伤害结果，不反向修改伤害、随机数、目标选择、BOSS规则或既有死亡流程。

### 2. 再做全队同步

- 本机负责自己草坪的权威累计，向房主发送低频绝对快照，建议每0.5至1秒一次；过关、胜负、换位前和退出时尽力补发最终值。
- 快照带对局/关卡/尝试标识、稳定玩家身份、序号，以及独立的BOSS与非BOSS有效伤害累计；总统计为两类之和，BOSS页只取BOSS部分，避免把展示开关绑定到底层数据。接收覆盖同版本快照而非重复相加。合法回退必须换尝试标识，不能靠永远取最大值修补。
- 房主校验实际连接与玩家身份、长度、非负范围以及BOSS不大于总统计等条件后汇总广播。最多六人；不发送每发子弹、每次跳伤的细粒度消息。
- 换位仅更新显示席位；掉线保留最后已知数字并标离线。重新连接在可证明同一人的情况下恢复，不用名字猜身份；进程重启另按检查点身份恢复处理。
- 加入或恢复同步发送完整表，旧关/旧尝试/过期序号一律不污染当前统计。结算收不到末包显示最后同步值，不能假称完全精确。
- 实施时才分配新消息和同步Build号；检查客户端编解码、直连、服务器中继允许的消息范围/长度。不能假定现有中继会自动转发新类型。
- 这是普通合作局统计，不是服务器逐帧复算的防作弊排行榜；不承诺能识别篡改客户端的伤害。

### 3. 界面与继续游戏

- 默认查看本关，本关统计与本轮累计分层保管，BOSS/非BOSS也独立记账；过关只重置本关，不重置本轮。高级选项切换范围或显隐均不清零。重开/失败回退跟随真实进度回退，不能把同一段失败重试反复加到通关存档。
- 继续游戏应与关卡快照/检查点同一代保存。可扩展显式版本化的附加块或配对统计文件，但必须有相同提交代号与校验，不能仅凭相同种子配对。
- 单独一份统计文件的原子写入不等于两个文件共同原子提交；若采用附加文件路线，需先设计代号/提交清单或保留上一代，避免崩溃后旧进度配新数字。
- 旧档没有历史数字不能追溯补算。清楚显示“从本次启用/恢复后统计”；不填假0冒充完整整轮历史。损坏或不匹配的统计数据只降级统计，不让玩家丢档。
- 若首版暂不做跨重启保存，则必须明确标为“本次游玩”，不能用“本轮累计”掩盖恢复后清零。此项需要在实现前定案。
