# 256 间房容量与大厅分页 · 2026-10-19

中继版本 `2026-10-19-room-min2-rooms256`，房间保护上限由 128 改为 256；连接保护上限保持 512，每房最多 6 人。两个限制同时生效；256 个两人房将用尽连接额度，不能据此承诺 1536 人或满载时仍有大厅查询空间。公网带宽仍为用户现有的 3 Mbps，容量数字不会增加带宽或保证实际稳定人数。

PC / Android 沿用 MOD81，游戏通信、存档和房间码格式不变。这里只扩展独立大厅查询，不需要同房其他玩家同时升级游戏逻辑。

## 分页兼容

- 原目录请求版本 1 保持每页 6 间，最多返回排序后的前 128 间；最后一页在偏移 126 处以 2 间和结束标记收尾，防止旧客户端收到偏移 132 后整页报错。
- 新目录请求版本 2 使用相同帧类型和条目格式，每页仍最多 6 间；最大页偏移 252，最后一页最多 4 间，可浏览全部 256 间。单页载荷仍最多 152 字节。
- 新客户端先查询版本 2；旧服务器拒绝并关闭连接时，客户端在原 5 秒查询期限内最多重新建立一次查询连接、改用版本 1。后续翻页继续使用协商后的版本；刷新最短间隔仍为 2 秒。该连接与队伍连接独立。
- 旧客户端仍可按房间码加入新服务器上的其他房间，原有版本、门禁、空位和重连凭据检查继续生效。
- 状态页的房间上限从中继常量自动读取，运行新服务器后显示 256。

## 验证

- Go 全套测试、竞态检测、静态检查通过。
- 真实 TCP 测试创建 256 间公开房，第 257 间被拒；退出一间后可重新创建。版本 2 全页枚举 256 个唯一房间，版本 1 枚举 128 间并正常结束；偏移 252 最后一页和原房间码加入通过。
- 使用生产 C++ `RoomDirectory::Client` 和生产 Win32 `NetLink` 测试偏移 0、126、132、252；旧服务器关闭版本 2 查询后回退到版本 1 查询通过。解码器覆盖非法版本、偏移、超出容量和非法下一页边界。
- PC Release、Android ARM64 原生库和包含全部资源的 APK 构建通过。APK 资源、原生库与签名在交付脚本中核对；本批未做手机实机安装或完整长局验收。
- Linux amd64 实际程序验证 CLI / JSON / CPU / RSS、512 连接边界、第 513 连接拒绝、256 房间边界、第 257 房间拒绝及清理归零。arm64 已编译并验证静态 ELF，未在该架构实际运行。

证据位于工作区 `tools/audit/rooms256-*`。本次包含工作区已有的 `room-min2` 中继规则，保留至少两名在线玩家才能在服务器房间开局的检查。

## 交付与上线

完整 PC / Android / Server 包位于工作区 `dist/PvZ-Online-MOD81-Rooms256-Full-20261019/`。PC 带游戏资源、中文和运行库；Android 为首次打开自动准备资源的完整 APK。更新保留存档；手机覆盖安装，勿先卸载。

本地验收更新到 `runtime/`，旧程序与存档备份放在 `runtime/` 外。公网更新仍需管理员替换中继并重启；重启会清空内存房间，因此应等待现有对局结束后维护。上传方法见 Server 目录中的服务器更新说明。
