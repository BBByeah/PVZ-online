# 双端 UI 重做计划（Build55 基线）

2026-10-16。用户补充要求：PC 端也重做 UI。因此本轮由“手机向现有 PC 对齐”扩展为“双端采用统一的新布局与信息结构”。当前是计划阶段，尚未修改游戏代码。

本文件在 PC 与 Android 仓库的 `docs/` 各保存一份，内容同步，作为本轮总计划。Android 的 `UI-UPGRADE-PLAN-BUILD55.md` 保留触摸、数据入口和精简验收细则；发生范围或顺序冲突时，以本总计划为准。旧 Build52/53 界面只作历史参照。

## 1. 目标与风格

保留植物大战僵尸原本的墓碑、木牌、图鉴纸面、种子包、钱罐和奖杯视觉，让联机与肉鸽新增功能看起来属于同一款游戏。PC 的功能和数值仍是共同玩法参照，但现有 PC 排版不再被视为必须照搬的终稿。

PC 与手机共同确定标题、内容分组、状态用词、按钮顺序及返回流程。PC 提供鼠标悬停和快捷键提示，手机扩大命中区域、减少多列小字；不要求两端控件坐标完全相同。中文与英文从排版开始共同考虑，长说明分页或换行，不靠缩到难读来塞满。

PC 保持 800×600 逻辑画布与现有等比无边框全屏。手机保持等比呈现并核对实际触摸面积。选中、按下、悬停、禁用和处理中有不同反馈；禁用同时给出文字原因。持卡时打开/关闭界面不会误种，弹窗和面板输入不得穿透。

## 2. 已核对的 PC 改版理由

以下来自当前源码，不是本次新增画面实测：

- `Lawn/CoopPlay.cpp`：队友列表把空席/自己也排成操作项；植物申请是两列文字按钮；借入状态及所有词条塞进固定75高说明区，借出确认也只有固定说明区。应重排内容并复用手机已有植物图/详情分页思路。
- `Lawn/Widget/OnlineDialog.cpp`：已有原版编辑框和石材按钮，但连接字段、状态与动作混在同一页；长状态文字会缩小字号。应重新组织连接前后两种内容重点。
- `Lawn/Widget/NewOptionsDialog.cpp`：本局词条已有分页和输入，但主要显示名称/层数，植物列表主要遍历永久 `mBuffs`。新查看器需要清楚呈现说明、临时借用和实际生效层数，不能仅把现有列表放大。
- `Lawn/Widget/RunModeDialog.cpp`、`RunPickDialog.cpp`：模式缩略图、奖励植物图、稀有度和拥有层数已存在。应重做分组与布局，保留已实现信息与行为，避免以重做名义退化成只有文字的卡片。
- 六席页和首页状态条已有共同实现；本轮补准备状态、上下文返回和信息层级。当前缺少对 UI 开放的每席本轮准备查询，不是缺少等待机制。
- PC 快捷消息及赠送相关绘制/输入主要在 `Lawn/Board.cpp`，手机在 `src/Lawn/BoardCoop.cpp`；业务状态可复用，但不能按同名文件机械覆盖。

基线：双端 Build55 / Protocol1；PC 代码 `b690bc64ca3833c86bfe874275a95d419969c273`，Android 代码 `4df6a3ddc2a8ef456aa7e5ea10ac7d9dfc6cf12a`。钱包/保存、赠送回执、取消借用和 readyEpoch 已修，UI 读取这些结果。完整双端对局验收仍未收口。

## 3. 双端页面范围

| 页面 | PC 重做内容 | 手机同步内容 |
|---|---|---|

| 联机房间 | 未连接突出创建/加入；已连接突出房间码、成员、席位和房主动作；直连作为清楚标注的配置区 | 对应信息分组，大输入区及软键盘适配，连接动作名称一致 |
| 席位和等待 | 六席卡片补本轮准备、断线、版本状态；等待页显示已准备人数和待准备者 | 可触摸查看席位，再返回原等待；战斗/等待期明确只读 |
| 模式和高级选项 | 模式卡、难度、续局信息分层；高级选项按规模/节奏/强化/场景等分组 | 同一选项、默认值与解释，允许分页；模式点击开局语义保持 |

| 战斗协作与观战 | 整理消息/表情/阳光选择面板、借用入口、短时通知、观战顶条；鼠标可发现并保留键盘路径 | 恢复消息/表情/阳光三个常驻按钮，保留借用/求援/观战和席位入口 |
| 协作借用/求援 | 有效队友卡、种子图选择、借入详情与确认分页；送达/取消状态可追踪 | 对齐相同内容和状态，复用已有手机分页能力 |
| 图鉴和本局词条 | 原版图鉴主体保留，整理说明与词条分页；重做本局查看器的分类、详情和有效层数 | 图鉴首屏可发现词条；新增本局查看器，区分可能获得与当前持有 |
| 暂停与设置 | 将语言、血量、本局词条、协作和既有选项有序分组；恢复游戏动作突出 | 同一名称，提供血量与划取阳光触摸设置；不依赖键盘 |
| 通关和异常提示 | 保留奖杯结算并整理结果/返回动作；断线、拒绝和版本问题说明原因与下一步 | 对齐 PC 完整结算反馈，替代仅一句消息；退出走已有保存/退关路径 |
| 商店、花园 | 纳入中文、按钮、返回及提示一致性检查；原版场景和交互主体保留 | 同步共同信息口径，保留现有额外内容与入口 |

Android 资源导入页是附加收尾项，PC 无需仿造一页；系统文件选择器、权限框保持系统行为。

## 4. 实施顺序与分批交付

### 第一批：共同控件与联机主路径

先确定石材/木牌按钮、标题、正文、状态提示的尺寸与颜色规范，复用两端现有绘制工具，不统一重写底层渲染框架。重排房间与六席等待页，用一组最终代表画面检验这套视觉是否成立。

房间中创建、加入、断开、席位、房主开始各有清楚归属；等待区只显示网络真实可知的状态。准备 false 统一叫“尚未准备”，不推测对方在选植物还是选奖励。每席查询匹配 readyEpoch；UI 不消费 ACK/RUN_GO 事件，也不另建放行条件。

这一批双端一起落地，不能只改手机后宣称 PC 完成。

### 第二批：战斗协作与操作反馈

双端共用消息、表情、阳光和借用的信息结构。手机三个常驻入口保持用户定案；PC 用鼠标入口及已有 T/E/G/B/V 等路径，并保留数字选卡与面板内数字选择的输入优先级。

PC 协作页改为队友列表 → 植物种子卡 → 词条详情/确认，不在75高区域堆全部借入内容。显示永久、临时和实际有效层数时调用既有规则。没有队友卡池数据时，明确“申请后由队友确认”，不假装展示对方可借库存。

送阳光显示扣100、收到90及回执；结果未知显示等待确认。借用取消未确认时保持处理中，重开面板可继续查看；不能仅因关闭窗口便显示已取消。观战和通知条控制遮挡，席位/目标不明时不猜测姓名。

### 第三批：词条、图鉴与设置

双端本局查看器统一为全局/植物/僵尸信息及可翻页详情；永久和临时借用分开说明，实际生效层数读取同一模型。图鉴明确展示“可获得词条”，保留原版说明、费用和冷却，不把图鉴目录与本局状态混用。

PC 支持现有滚轮/翻页键；手机用显式按钮。普通手机能触摸切换植物/僵尸血量。划取阳光属于遗漏功能，作为本批关联的独立提交补齐并定点验证，不能只画设置却无效果。

### 第四批：主菜单、模式、奖励与结算

按同一视觉规范整理主菜单与模式/高级选项，重排三选一、投票、钱包和费用操作区，手机补完整通关反馈。PC 这些页面也是本轮正式改版范围，不再只做抽查或作为手机截图参照。

先修主路径上最明显的布局与信息层级，再处理商店/花园的具体文字和导航问题。原版额外模式保留；不因 UI 改版删功能或改购买/掉落规则。

### 第五批：收尾与产物

核对中文/英文、长名、空列表、六席、断线与处理中状态。按需完成 Android 资源页主题。记录双端提交、PC/APK 来源、实际安装版本、代表画面及未验边界；完整对局未通过前不修改 `onlineGameReady=false`。

## 5. 约束与精简验收

- 不改玩法数值、价格、赠送100→90/冷却、借用机制、v17存档、准备和判胜语义；确需改协议另列同批双端兼容任务，纯展示预计保持 Build55。
- 本轮暂不更换画布分辨率、实现宽屏重排或重画所有美术。优先使用原版素材，资源不上传。
- 每个独立批次检查 diff、增量构建和相关运行路径，同批写玩家更新日志。视觉页核对呈现尺寸、测量关键区域；诊断只覆盖本次布局，移除临时插桩。
- 截图按“布局类型”抽取，不逐植物或逐控件取证。先复用历史证据；预计双端整轮约6–8张关键最终图，异常仅在定位需要时补图。PC和手机各有实际代表画面，不能只看一端。
- 鼠标悬停/点击、键盘面板优先级、触摸移出松手、关面板不误种各做定点检查。网络使用稳定云中继检查状态变化，沿用 Build55 事务测试结果；未改业务不重跑全套 buff/网络回归。
- 涉及游戏运行先备份用户数据，结束恢复并核对；不终止用户正在进行的对局。没有游戏代码变化的计划阶段不构建、不安装、不运行这些检查。

## 6. 完成标准

PC 和手机各自的主路径页面完成改版；共同功能名称、内容和反馈一致，玩家不用猜“现在在等谁/能做什么/操作是否成功”。PC 鼠标与键盘可用，手机触摸可用；旧有功能与数值保留。完成记录须区分源码完成、已构建、已安装和实际运行验收，不能把任一阶段等同全部完成。
