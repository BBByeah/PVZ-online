2026-10-16 初稿，2026-10-17 追加用户定案。MOD_BUILD 56 已落地两项定案（护心最高一层、档 2 两屏投票）。本稿是三项讨论的素材整理：**更多词条与分档、奖励机制、过难条目拆分**。第 0 节为本聊天最新定案；后文保留历史讨论素材，冲突时以第 0 节为准。除第 0 节外，候选和数值均未定案。

## 0. 2026-10-17 用户定案：拆分免控，BOSS 保留软控窗口

用户原话：“把免控拆成免硬控和减少软控时间两个词条；boss同理，不能完全免控”。随后确认软控持续时间采用“缩短 50%（推荐）”；该选项的完整提问同时说明新词条和 BOSS 均采用减半、最高一层，BOSS 同时获得该词条时不重复缩短。

| 对象 | 确认规则 |
|---|---|
| 免硬控词条 | 免疫冰冻、黄油定身、击退、大蒜换道和魅惑；不免疫减速。最高一层。 |
| 软控缩时词条 | 减速持续时间缩短 50%，减速幅度不变。最高一层；与免硬控独立选取。 |
| 三种关底 BOSS | 红眼、橄榄球、冰车均保留硬控免疫，允许软控生效；软控持续时间减半，幅度不变。 |
| BOSS 与软控缩时叠加 | 只减半一次，不继续减到四分之一，更不能减成完全免控。 |

同日追加用户定案：“橄榄boss不能吃植物不阻挡僵尸buff”。此处“吃 buff”指获得词条效果：**橄榄球关底 BOSS 不受“无视阻挡”影响，遇到植物仍须停下啃食，不能直接穿过植物。** 包括接力后的带标记橄榄球 BOSS；普通橄榄球僵尸的词条规则不随本条改变。该追加不调整 BOSS 啃食伤害，也不扩展为其他类型 BOSS 的新规则。

控制分类与边界：

- 软控覆盖普通冰缓、地刺和三叶草附带减速、腐臭之息、霜甲、仙人掌缓行；不能只改冰弹而漏掉直接写计时器的入口。
- 寒冰菇等同时包含冰冻与减速的效果分别结算：免硬控挡冰冻，减速仍然生效；若对象有软控缩时或是关底 BOSS，减速时间减半。
- 缩时只在施加/刷新效果时计算一次；刷新沿用保留较长剩余效果的规则，不把已有剩余时间再次减半。
- BOSS 按关底标记识别，包括接力后的 BOSS；普通同类型僵尸不因此获得 BOSS 专属抗性。原版特殊状态/普通车型的固有规则另行保留。
- 冰车移动有独立速度分支，实施时须确认软控确实降低位移速度，不能仅增加计时器或减慢动画。

实施范围：PC 与 Android 同步词条、控制入口、投票文案及查看说明；词条池从 8 条变为 9 条时，需一并处理联机层数快照、载荷长度、版本和旧检查点兼容。两条已满层词条应退出候选池，第二屏替换候选时同样过滤。兼容迁移的具体实现仍须核对，不能因本讨论擅自丢弃旧进度。

## 2. 讨论一：更多词条与分档

**结构观察**：现池 4 数值 + 4 质变。质变条天然带「3★ 相」（≥1 层全生效，与植物侧 3★ 质变口径同构）——分档最自然的切法是按轴：

- 1★ 数值条（迅捷、再生）/ 2★ 强数值（铁壁、狂食）/ 3★ 质变（护心、免控、墓碑者、无视阻挡）→ 2/2/4 或其他配比
- 分档后的抽取：三候选按 ★ 加权（低★常见、高★稀有），还是随局数升档（前期低★后期高★）——两个方向都通，语义不同（前者=稳定预期，后者=难度曲线）
- 现状等权洗牌没有权重轴；植物侧已有 k/e/稀有度三轴可参照搬

**硬成本（扩池唯一拦路虎）**：池 >8 → `mZombieBuffStacks[8]` 扩容 → 检查点 v17→v18 + 重连快照 `mZombieStacks` 8 字节段扩容 + **START_LEVEL 载荷变（客户端层数只信 START_LEVEL 快照）**→ `START_LEVEL_PAYLOAD_SIZE` 常量必须随改（51bc30d 先例：常量漏改=开局族 nettest 全红）→ MOD_BUILD 再抬。扩到 16 = 字节 ×2，一档到位比逐次扩省版本号。
**与两屏制的联动**：池 ≥9 第二屏剔除后仍有解；若缩池 <5 两屏候选会枯竭——扩池是两屏制的保障而非对立面。

**池级结构问题（扩池绕不开的三件事）**：
1. **稀释数学**：每屏 3 候选无放回，单条上屏率=3/池。8 条时 37.5%、12 条 25%、16 条 18.75%；一局 4~8 屏，16 条池里多数词条一局最多见 1 次。等权洗牌下「想要的压力组合」越来越随机——分档/权重轴（植物侧 k/e 先例）从可选变成迟早要面对。
2. **到顶条占票**（现状缺口，非扩池才有）：迅捷等封顶条投满 cap 后再次被选=废票（效果钳在 cap、票白投、横幅照报）。候选是否剔除已满层条/废票是否退还，扩池前要定口径。
3. **场景有效性**：墓碑者屋顶/泳池静默白票的教训要制度化——每条新词条带场景有效性声明，roll 时按场景过滤候选，而不是投完才发现白票。

**每条新词条的固定成本清单**：中文名（位图字库 1419 字审计）+英文文案、投票框/查看器/横幅三处显示、Android 镜像（OnlineGame 分叉手工重放）、docs/07+08、平衡建模（僵尸侧无费用分母：估值≈真值×生效速度×频率，「票权」就是成本——票数稀缺是唯一约束）。

**跨轴依赖与矛盾汇总**：B3 阻塞于 boss48 合并；C4 与免控拆分同轴二选一；C1/C2=变相回滚植物侧数值批（跨批联动过 docs/07 总账）；A1×席位乘数×名单 19 三方关系未过；E 轴与花园批经济方向相反；D1 即死口径不定则数值无意义；B4 与迅捷相邻。
**创新向观察**：现有 8 条全是「常驻」型（投完即恒定生效）；A4 旗波倍增/D2 巨人分裂/F1 遗言自爆/D3 阵地援军是「时刻」型（在特定时刻发难）。若扩池+分档一起做，「1★ 常驻、3★ 时刻」是现池没有的节奏维度（口径示意，非定案）。

## 3. 讨论二：奖励机制

**现状定性**：投票是纯加压仪式——所有结果都让僵尸更强、弃权也保底随机 1 条（47 定案）、默认档还是 1（MOD54）。玩家参与投票的现实动机只有「选相对最轻的一条」，仪式感是负反馈里的。

方向清单（互不排斥，可叠加）：

| 方向 | 内容 | 张力 |
|---|---|---|
| A 风险收益对称 | 档位越高通关奖励越好（币/重摇券加成；档 2 通关 = +N 券） | 「奖励高难」与「默认难」是相反的入门坡；奖励落点（花档案钱包）已存在 |
| B 投票参与奖励 | 投中获胜条目的席位得下屏三选一 +1 重摇券 | 个人奖励驱动表态；六席位纪律下「人人有份」与「胜者独得」要选边 |
| C 击败掉落 | 带 N 层强化的僵尸掉币概率提升 | 向经济系统输血，与金币经济盘「出路」议题联动；数值出口要过 docs/07 |
| D 剥层净化 | 植物侧新词条（三选一池）：每击杀 X 只剥 1 层僵尸 buff | 把加压变成可逆过程；跨系统（植物 buff 表 ↔ 僵尸 buff 表）新依赖 |
| E 选择权本身 | 两屏制已落地——每屏一次三选一即参与感 | 已兑现，无需再动 |

**核心矛盾**：A/B/C 都在奖励「接受更多加压」，而系统现状在默认加压（档 1 默认开）。若同批做「奖励」与「默认档」，两者取向需要对齐后再定数值。

## 4. 讨论三：过难条目拆分

MOD56（护心封顶）之后剩余的难源与拆法（拆 = 单条效果降档/换轴，池子变大）：

| 条目 | 难源 | 拆法候选 |
|---|---|---|
| 免控 | ≥1 层全免：魅惑菇（3★、冷却已 ×6）、三叶草全场减速、大蒜换道、寒冰系、黄油一票全废——一票废一系，植物侧无穿透对冲 | a. 拆「免疫减速/冰冻」+「免疫魅惑/黄油」两条分票权；b. 降为「控制效果减半」；c. 保留全免、出植物侧「穿透控制」词条对冲（与剥层 D 同族） |
| 铁壁 | ×1.5^层 复利（4 层 ×5.1、8 层 ×25.6），与 boss ×3 顺位乘数叠乘后 boss 血 ×15 起 | a. 封顶降 ×4；b. 改加法 +50%/层；c. 拆「普通僵尸/巨人」两条 |
| 狂食 | ×2^层（4 层 ×16/口），坚果瞬穿 | a. 封顶 ×8；b. 改加法 +100%/层；c. 保持、靠「封顶层」统一管理 |
| 无视阻挡 | 巨人已豁免，但橄榄/冰车 boss 不是巨人 → 投中即 boss 直冲 | a. boss 豁免补齐（一行）；b. 降为「啃咬 ×3 速」（还啃但快） |
| 墓碑者 | 屋顶/泳池非草皮 = 静默白票 | 严格说不是拆条是流程：roll 时按场景过滤无效候选 |

**拆分的代价与约束**：
- 池子变大 → 协议/检查点成本（与讨论一共用，见 §2 硬成本）
- 「弱化版」与「原版」同池共存会违反「同株同量必须换轴」的估值纪律（同效不同档=重复轴）——更干净的做法是**直接改值**（走 docs/07 数值批）而非拆成两条
- 免控对冲词条（c 方向）属植物 buff 批的范围，不混僵尸 buff 批；跨表依赖要过 buff修改指导.md 的组合规则

## 5. 跨项矛盾汇总

1. **扩池 vs 协议冻结**：讨论一、三共用同一条硬成本；扩池一次到位（16）比分批扩省版本号。
2. **奖励 vs 默认难度取向**：讨论二的所有方向都在给「接受加压」发糖，需要与默认档 1 的取向先对齐。
3. **拆条 vs 改值**：讨论三里多数「难源」用 docs/07 数值批直接改值即可达成，拆条只在「想要两条独立票权」时才必要（免控 a 是唯一真正需要拆的）。
4. **叠层流**：两屏制当前剔除已入条目（档 2 = 两条不同）；若未来想开「同条叠层」打法，是反方向选项，与「拆分降难」对撞。
